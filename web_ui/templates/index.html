Hand this to your QAs — the only format that gives 100% perfect YAML.

The 10-column template

Fill one row per step, not one row per scenario. Repeat the TC ID + Scenario columns on every step row of the same test.

Worked example

A real Customer-search test, written one row per step:

TC IDScenarioScreenStepActionTargetValue
TC-CUST-001Customer search by Last Namecustomerlist1open_search
TC-CUST-001Customer search by Last Namecustomerlist2fillLast NameSmith
TC-CUST-001Customer search by Last Namecustomerlist3clickSearch
TC-CUST-001Customer search by Last Namecustomerlist4assert_no_errors

Produces this YAML:

tests:
- screen: customerlist
  name: Customer search by Last Name
  steps:
  - action: open_search
  - action: fill
    target: Last Name
    value: Smith
  - action: click
    target: Search
  - action: assert_no_errors

Tips

  • Use one row per step, not one row per scenario. Repeat TC ID + Scenario on every step row.
  • Screen must match a catalog screenname (e.g. customerlist, receiptslist, shippingorderslist).
  • Target accepts #id, a label like "Last Name", or a button name like Save.
  • Empty Target/Value is fine — actions like open_search or assert_no_errors don't need them.
  • Expected is informational. Use assert_visible, assert_text, or assert_no_errors if you want it actually checked.
  • Step numbers within a scenario decide run order. Order across TC IDs doesn't matter.

Don't have the template? Legacy prose also works

The converter will still try to translate free-prose Excel files like the ones already in circulation. Anything the regex can't map becomes a todo step that's preserved verbatim — the YAML still runs, the run log flags it, and a QA can edit the rest later. For 100% accuracy, use the template.
